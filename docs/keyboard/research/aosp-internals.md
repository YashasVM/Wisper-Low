## 1. Suggestion pipeline and autocorrection gates

### Candidate collection and ordering

`Suggest.getSuggestedWords()` dispatches typing and gesture input separately. The typing path gets a `ComposedData` snapshot, n-gram context, keyboard proximity handle, settings, and session ID. Both typing and gestures use session ID `0`. The native dictionary is therefore one part of a wider pipeline, rather than the component that decides whether a separator should replace a word. [java/src/com/android/inputmethod/latin/Suggest.java:47-51](https://github.com/aosp-mirror/platform_packages_inputmethods_latinime/blob/127336e9f29d69607eab55982324b210279ae8c5/java/src/com/android/inputmethod/latin/Suggest.java#L47-L51) [java/src/com/android/inputmethod/latin/Suggest.java:98-110](https://github.com/aosp-mirror/platform_packages_inputmethods_latinime/blob/127336e9f29d69607eab55982324b210279ae8c5/java/src/com/android/inputmethod/latin/Suggest.java#L98-L110)

`DictionaryFacilitatorImpl.getSuggestionResults()` queries main, contacts, user-history, and personal dictionaries, in that order. A `SuggestionResults` bounded sorted set merges their answers. It has capacity `SuggestedWords.MAX_SUGGESTIONS = 18`, sorts by descending integer score, then shorter code-point length, then lexical string order, and discards its worst result when full. Source dictionaries remain attached to candidates. ### Exact safety gates

In this snapshot `SHOULD_AUTO_CORRECT_USING_NON_WHITE_LISTED_SUGGESTION = false`. A word allows correction when the highest remaining candidate is an allowlist entry, or when the considered string has more than one UTF-16 character and had no exact suggested-word source. This is how valid typed words are normally protected. An allowlist can override that protection. [java/src/com/android/inputmethod/latin/define/DecoderSpecificConstants.java:24-37](https://github.com/aosp-mirror/platform_packages_inputmethods_latinime/blob/127336e9f29d69607eab55982324b210279ae8c5/java/src/com/android/inputmethod/latin/define/DecoderSpecificConstants.java#L24-L37) [java/src/com/android/inputmethod/latin/Suggest.java:172-198](https://github.com/aosp-mirror/platform_packages_inputmethods_latinime/blob/127336e9f29d69607eab55982324b210279ae8c5/java/src/com/android/inputmethod/latin/Suggest.java#L172-L198)

After that protection, `Suggest` refuses automatic correction when any of these holds:

- Correction is disabled by the caller or field settings.
- The typed word is protected by the rule above.
- Results are predictions rather than a composing word.
- There are no results.
- The word contains digits.
- The word has more than one uppercase character. `isMostlyCaps()` literally means `mCapsCount > 1`, not a majority percentage.
- Composition was resumed after editing an existing word.
- No initialized main dictionary exists. Contacts alone must not turn `will` into a contact named `Will`.
- The top result is `KIND_SHORTCUT` rather than `KIND_WHITELIST`.

Every gate is in [java/src/com/android/inputmethod/latin/Suggest.java:200-246](https://github.com/aosp-mirror/platform_packages_inputmethods_latinime/blob/127336e9f29d69607eab55982324b210279ae8c5/java/src/com/android/inputmethod/latin/Suggest.java#L200-L246); the caps definition is [java/src/com/android/inputmethod/latin/WordComposer.java:343-354](https://github.com/aosp-mirror/platform_packages_inputmethods_latinime/blob/127336e9f29d69607eab55982324b210279ae8c5/java/src/com/android/inputmethod/latin/WordComposer.java#L343-L354).

Otherwise `AutoCorrectionUtils` accepts allowlist candidates immediately, rejects candidates lacking `KIND_FLAG_APPROPRIATE_FOR_AUTO_CORRECTION`, and requires normalized score `>= threshold`. ### Normalized score and setting values

The actual native normalization, including its current early return and legacy unreachable implementation, is detailed in section 2. Its active equation is `normalized = (score / 1_000_000) * (1 - editDistance(typed, candidate) / candidateCodePointLength)`. Zero-length candidate or nonpositive score returns `0`. The threshold numbers have meaning only on this native score scale. They cannot be transplanted onto Wisperlow's `ln(frequency + 1) - editPenalty + contextBonus` score. [native/jni/src/utils/autocorrection_threshold_utils.cpp:70-89](https://github.com/aosp-mirror/platform_packages_inputmethods_latinime/blob/127336e9f29d69607eab55982324b210279ae8c5/native/jni/src/utils/autocorrection_threshold_utils.cpp#L70-L89) [android/keyboard-core/src/main/kotlin/com/wisperlow/mobile/keyboard/Lexicon.kt:48-70](/home/yvm/code/Wisper-Low/android/keyboard-core/src/main/kotlin/com/wisperlow/mobile/keyboard/Lexicon.kt:48) [android/keyboard-core/src/main/kotlin/com/wisperlow/mobile/keyboard/Lexicon.kt:85-151](/home/yvm/code/Wisper-Low/android/keyboard-core/src/main/kotlin/com/wisperlow/mobile/keyboard/Lexicon.kt:85)

The resources define these modes:

- Off, index `0`: `Float.MAX_VALUE`, represented by `floatMaxValue`; the separate correction-enabled flag also prevents correction.
- Modest, index `1`: `0.185`.
- Aggressive, index `2`: `0.067`.
- Very aggressive, index `3`: negative infinity, represented by `floatNegativeInfinity`. The other safety gates still apply.
- Plausibility: `0.065`, a separate threshold intended to judge language plausibility.

These are exact resource values, not estimates. The current `SettingsValues` constructor chooses modest when its autocorrect boolean is on, and off otherwise; the presence of four resource entries does not mean the inspected UI exposes all four modes. The parser resolves the marker strings and falls back to `Float.MAX_VALUE` for invalid settings. [java/res/values/config-auto-correction-thresholds.xml:21-47](https://github.com/aosp-mirror/platform_packages_inputmethods_latinime/blob/127336e9f29d69607eab55982324b210279ae8c5/java/res/values/config-auto-correction-thresholds.xml#L21-L47) [java/src/com/android/inputmethod/latin/settings/SettingsValues.java:153-177](https://github.com/aosp-mirror/platform_packages_inputmethods_latinime/blob/127336e9f29d69607eab55982324b210279ae8c5/java/src/com/android/inputmethod/latin/settings/SettingsValues.java#L153-L177) [java/src/com/android/inputmethod/latin/settings/SettingsValues.java:324-350](https://github.com/aosp-mirror/platform_packages_inputmethods_latinime/blob/127336e9f29d69607eab55982324b210279ae8c5/java/src/com/android/inputmethod/latin/settings/SettingsValues.java#L324-L350)


## 2. Native decoder and tap geometry

### What Wisperlow already has

I read `Lexicon.kt` and `Qwerty.kt` before LatinIME. They moved during research from `android/app/src/main/java/...` to `android/keyboard-core/src/main/kotlin/com/wisperlow/mobile/keyboard/`. Wisperlow already uses touch-weighted Damerau-Levenshtein distance, repeated-letter insertion/deletion discounts, transpose discounts, length limits, unigram log counts and learned bigrams. `Qwerty.kt:11-44` hardcodes QWERTY row offsets `0, 0.5, 1.5`, adjacency within one row and `1.01` horizontal key widths, and slip cost `clamp((EuclideanDistance-0.5)/0.8, 0.25, 1)`. `Lexicon.kt:110-131,468-506` allows weighted distance `0.7` for length <=2, `1` for length <=4, `2` otherwise; slang allows none. It uses `0.7` for a nearby substitution or transposition and `0.3` for a repeated-letter omission/insertion. A first-letter filter admits only the typed first letter, typed second letter, or an adjacent key. This is a partial spatial model, but it gives an exact character match zero spatial cost even if the tap was near an edge (`Lexicon.kt:481-486`). AOSP scores tap displacement even when its primary key label matches the candidate.

### Session, traversal, error budget and queues

`DicTraverseSession` owns dictionary/context, previous word IDs, proximity states, traversal queues and a bigram cache. Initialization obtains the dictionary header's multiword cost multiplier and resolves preceding words with lowercase fallback. Setup supplies code points plus x/y/time/pointer arrays to `ProximityInfoState`; ordinary typing has one pointer, geometric input two. The implementation recognizes geometric input by `maxPointerCount == 2`, with a source comment acknowledging that this is a heuristic. See [dic_traverse_session.cpp:27-79](https://android.googlesource.com/platform/packages/inputmethods/LatinIME/+/127336e9f29d69607eab55982324b210279ae8c5/native/jni/src/suggest/core/session/dic_traverse_session.cpp#27) and [defines.h:273-280](https://android.googlesource.com/platform/packages/inputmethods/LatinIME/+/127336e9f29d69607eab55982324b210279ae8c5/native/jni/src/defines.h#273).

The search expands lexicon trie nodes, not a scan over every similarly sized word. Each node can consume a matching/proximity touch, substitute, skip an input touch, omit a dictionary letter, transpose two touches, complete beyond the current input, or open a second word. Insertions/transpositions use deferred lookahead nodes because they need the next touch. Omissions immediately inspect the following dictionary child for a match/proximity, limiting impossible branches. Exact matched code points or proximity matches must exist somewhere in a terminal; a candidate made entirely of edit operations/completions is rejected. See [suggest.cpp:103-252](https://android.googlesource.com/platform/packages/inputmethods/LatinIME/+/127336e9f29d69607eab55982324b210279ae8c5/native/jni/src/suggest/core/suggest.cpp#103) and [suggest.cpp:306-392](https://android.googlesource.com/platform/packages/inputmethods/LatinIME/+/127336e9f29d69607eab55982324b210279ae8c5/native/jni/src/suggest/core/suggest.cpp#306).

There is no fixed "maximum two edits" counter gate in this typing policy. More ordinary edits are allowed only while `spatialDistance / (inputIndex + 1) < 0.095`. The implementation tests normalized **spatial** distance, despite `suggest.cpp:157` saying "compound" in its comment. Intentional omissions remain eligible even beyond that gate. `MAX_SPATIAL_DISTANCE = 1.0` caps a point-to-key distance; it is not a maximum whole-word error count. See [typing_traversal.h:42-73,151-166](https://android.googlesource.com/platform/packages/inputmethods/LatinIME/+/127336e9f29d69607eab55982324b210279ae8c5/native/jni/src/suggest/policyimpl/typing/typing_traversal.h#42), [dic_node.h:281-289](https://android.googlesource.com/platform/packages/inputmethods/LatinIME/+/127336e9f29d69607eab55982324b210279ae8c5/native/jni/src/suggest/core/dicnode/dic_node.h#281) and [scoring_params.cpp:21,65](https://android.googlesource.com/platform/packages/inputmethods/LatinIME/+/127336e9f29d69607eab55982324b210279ae8c5/native/jni/src/suggest/policyimpl/typing/scoring_params.cpp#21).

### How frequency/context and spatial cost combine

The decoder accumulates spatial costs and language costs separately. ### Final score and normalized autocorrection score

Let `D` be output compound distance and `n` input count. Initial floating output score is `1 - D/(1.1214 + 0.1*n)`. Forced multiword output adds `1.0`. If dictionary headers enable exact-match boosting, an exact match adds `1.1`, with wrong-case `0.01`, missing-accent `0.02` and digraph `0.03` deductions. "Exact" permits only wrong case, missing accent, or digraph flags. Probability-zero words receive the `1.1` boost only for a perfect match with no error flags. ## 3. InputLogic behaviors

### Space is a state machine

AOSP defines five integer states. `NONE=0` means ordinary insertion; `DOUBLE=1` records a double-space conversion; `SWAP_PUNCTUATION=2` records a punctuation/space swap; `WEAK=3` records a real space after accepting a composing word; `PHANTOM=4` records a deferred space after a suggestion pick. Phantom is not a character already in the editor. It lets the next key decide whether a space belongs before it. ### Older forgetting curve still present

The backward-compatible level model uses `ForgettingCurveUtils`, whose constants are useful historical reference but must not be presented as the current v403 probability calculation:

- Maximum level `15`, minimum visible level `2`.
- Maximum elapsed step index `31`, giving `32` steps per level duration.
- One counted occurrence raises a level, with bounds and initialization rules in the update function.
- One level duration is `15 * 24 * 60 * 60` seconds. Each step is `40,500` seconds, or 11.25 hours.
- A level-zero entry is retained until its elapsed-step count reaches `30`.
- Periodic decay check interval is `2 * 60 * 60` seconds. Entry count at `1.2 * maximum` can force collection independently of time.
- Probability scale multiplier for doubling is `8`; the n-gram bias helper returns `(n - 1) * 8`.
- Table IDs are weak `0`, modest `1`, strong `2`, aggressive `3`. These describe history strength, not the autocorrect setting modes.
- Weak base probability uses integer division `127 / 2^(15-level)`. Other bases are `8*(level+1)`, `9*(level+1)`, and `10*(level+1)`. Comments claiming maxima should not replace this executable formula; for example, the strong formula reaches `144` at level 15 despite a `140` comment.
- At visible levels, the table interpolates exponentially as `initial * (initial/end)^(-elapsedStep/32)`, converts to integer, and clamps to the valid probability range. Below visible level it returns no probability.

#### Resampling and scoring

Both user and ideal paths are resampled nominally to 200 samples at approximately equal arc-length spacing. The implementation uses `pathLength / numPoints`, starts with the first point, tracks fractional rounding error, and fills the one-point case with the same location. For shape comparison it scales by the longest bounding-box side, clamped to at least `0.00001`, then centers using the bounding-box midpoint. This removes translation and uniform size while preserving aspect ratio. It is not dynamic time warping. [StatisticalGlideTypingClassifier.kt:198-218,535-613](https://github.com/florisboard/florisboard/blob/fe1241f4921b3eae923571ff7a3e113a7e10d677/app/src/main/kotlin/dev/patrickgold/florisboard/ime/text/gestures/StatisticalGlideTypingClassifier.kt#L198-L218), [resampling and normalization](https://github.com/florisboard/florisboard/blob/fe1241f4921b3eae923571ff7a3e113a7e10d677/app/src/main/kotlin/dev/patrickgold/florisboard/ime/text/gestures/StatisticalGlideTypingClassifier.kt#L535-L613).

Let `R = min(firstKey.width, firstKey.height)`:

- Shape distance `Ds` is the **sum**, not mean, of the 200 Euclidean distances between matching normalized sample points.
- Location distance `Dl` is `sum(abs(dx) + abs(dy)) / 200 / 2` using unnormalized screen coordinates.
- Convert each to a zero-mean Gaussian density, with `sigmaShape = 22.08` and `sigmaLocation = 0.5109 * R`.
- Rank by ascending `1 / (Gaussian(Ds, 0, 22.08) * Gaussian(Dl, 0, 0.5109R) * (255 * providerFrequency))`. Smaller reciprocal means a better candidate. This is a ranking weight, not a calibrated probability of correctness.
- Keep only the requested count in sorted order. Deduplicate loop/non-loop forms when a better weight is encountered. The manager's intended maximum is 8; its in-progress preview requests one visible candidate. `gestureCompleted` is accepted by the classifier API but does not alter this statistical implementation.
