Legal notice for Wisperlow romanization assets
===============================================

Scope
-----

This notice covers the romanization word-pair assets built from open data by
`android/tools/indic/build_indic_pairs.py`:

- `android/tools/indic/reference/hi.tsv`  (Hindi, Devanagari)
- `android/tools/indic/reference/kn.tsv`  (Kannada, Kannada script)

These are offline research references. They are excluded from the Android APK;
the app's Hindi and Kannada modes output Latin text. No proprietary data was used
in these references.

Source data [2] — Dakshina v1.0 (CC BY-SA 4.0)
----------------------------------------------

Source: the Dakshina v1.0 *word-lexicon train split only*:

- `hi/lexicons/hi.translit.sampled.train.tsv` (44,204 pair rows)
- `kn/lexicons/kn.translit.sampled.train.tsv` (50,624 pair rows)

Only the word-lexicon `*.train.tsv` files are used. The dev and test lexicons
are refused at the builder's CLI and are never opened, so no evaluation data
enters the asset. The full-sentence `romanized/` tree (which holds
validation-derived sentences and their romanizations) is likewise never read.

Dataset page: https://github.com/google-research-datasets/dakshina
Archive: https://storage.googleapis.com/dakshina/dakshina_dataset_v1.0.tar
Paper: Roark, Wolf-Sonkin, Kirov, Mielke, Johny, Demirşahin, and Hall,
"Processing South Asian Languages Written in the Latin Script: the Dakshina
Dataset", LREC 2020, pp. 2413-2423,
https://www.aclweb.org/anthology/2020.lrec-1.294

License declaration of the source (quoted from the dataset README):

  "The dataset is licensed under CC BY-SA 4.0."

License URI: https://creativecommons.org/licenses/by-sa/4.0/

The Dakshina lexicon layout is `native<TAB>romanization<TAB>attestations`. The
lexicons are partitioned by native-script word, so a word in the train lexicon
never appears in the dev or test lexicons. There are 25,000 native word types
in the Hindi and Kannada training lexicons.

Modifications
-------------

Starting from the sources' `(romanization, native word, count)` rows, the
builder applies the following modifications. No sentence, context or
raw-corpus text is retained; only word-level pairs are kept.

- Aksharantar: only the train split is read; only rows from the CC0 mined
  sources (Wikidata, Samanantar, IndicCorp) are kept; exact `(roman, native)`
  pairs are aggregated by counting their rows.
- Dakshina: only the train word-lexicon split is read; the `(native, roman,
  attestations)` triples are lower-cased on the roman side, NFC-normalized on
  both sides, and stripped of ZWJ/ZWNJ.
- Both sources: strings are lower-cased to the ASCII `a-z` key alphabet on the
  roman side and restricted to letters and combining marks of the target
  script on the native side; URL/email/domain junk, control characters,
  digits, punctuation, mixed-script words, over-long fields and malformed
  rows are dropped.
- Selection: all valid Dakshina train-lexicon pairs are placed first (capped
  at 8 romanizations per native word), then Aksharantar mined pairs fill the
  remaining budget, up to 100,000 pairs and 6,000,000 bytes per language.
- Counts: the per-pair `count` column holds the positive attestation count of
  that exact pair within its source. Counts from the two sources come from
  different collection methods and are never summed or compared; on an
  identical pair (not observed in the shipped files) the Dakshina count is
  kept. Unmodified source files used as input are identified by sha256 in each
  TSV header.

Generation
----------

Historical generation command (before these files moved out of app assets):

    python3 -I android/tools/indic/build_indic_pairs.py \
        --hi-zip hin.zip \
        --kn-zip kan.zip \
        --hi-dakshina hi.translit.sampled.train.tsv \
        --kn-dakshina kn.translit.sampled.train.tsv \
        --out-dir android/app/src/main/assets/indic \
        --max-pairs 100000 --max-bytes 6000000 --split train

The zips are the Aksharantar per-language archives (aksharantar-hin.zip,
aksharantar-kan.zip) from the Aksharantar dataset page; the Dakshina TSVs are
the word-lexicon train files from
`dakshina_dataset_v1.0.tar` (`<lang>/lexicons/`). The builder is deterministic:
the same inputs and flags produce byte-identical TSVs.
